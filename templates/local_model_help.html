How to choose a local model

A "local model" runs the language model on your own computer — no API key, no internet account, nothing sent to a company's server. You just tell the app which model to use, and it downloads it once.

Where models come from

Open language models are published on the Hugging Face Hub — think of it as a huge public library of models (a bit like GitHub, but for AI models). Each model lives at an address called a repo id, written as author/model-name, for example unsloth/SmolLM2-135M-Instruct-GGUF.

To use a model here, you copy its repo id into the "Local model path or Hugging Face repo id" box. The first run downloads it to your computer; after that it is cached and loads instantly.

The three things to look for

  1. "GGUF" in the name. This app's local engine reads a file format called GGUF. Pick a repo whose name ends in -GGUF (e.g. ...-Instruct-GGUF). The app automatically picks a good compressed version inside it, so you don't have to choose a file.
  2. "Instruct" (or "Chat") in the name. These models are trained to follow instructions (your prompts). Plain "base" models just continue text and are usually not what you want for agents that rewrite stories.
  3. A size that fits your machine. Model size is measured in parameters (M = million, B = billion). Bigger = writes better, but needs more memory (RAM) and runs slower. See the table below.

How big a model can I run?

The rough rule: the model needs about its "size in GB" of free memory, plus a bit. On a normal laptop without a dedicated graphics card, stay small. If you have a recent Mac (M1/M2/M3/M4) or an NVIDIA GPU, you can comfortably go to ~7–8B.

Finding your own

Browse huggingface.co/models (filter by the GGUF library). Open a model page, and copy the repo id from the top of the page (author/model-name). Prefer models with many downloads — they are usually the reliable, well-tested ones.
